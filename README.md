# vin-rouge v2 — 酒类分销进销存

当前版本：**v2.11.0**（2026-11-26，见 [版本演变](#版本演变)）

单人起步、多管理员共用的极简进销存：FastAPI + SQLite，单文件 `app.py` + 单文件 `static/index.html`，依赖只有 fastapi、uvicorn、pillow。

> 版本规则（单点管理）：唯一版本源是 `app.py` 里的 `APP_VERSION`。升版时只改它，再在下面 [版本演变](#版本演变) 加一条记录；前端页脚、登录页、`/api/version`、`/api/config` 都会自动同步，不要在别处手写版本号。

## 部署

```bash
git clone https://github.com/Tao314/vin-rouge.git /opt/vin-rouge
cd /opt/vin-rouge
bash install.sh
```

`install.sh` 会做：建虚拟环境并装依赖、写 systemd 服务 `vin-rouge`、启动服务。服务监听 `127.0.0.1:9000`，访问 http://127.0.0.1:9000。对外访问请在前面加 Nginx 或 Caddy 反代并配 HTTPS，例如 Caddyfile：

```
your.domain {
    reverse_proxy 127.0.0.1:9000
}
```

本地开发运行（不用 install.sh）：

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
./.venv/bin/uvicorn app:app --host 127.0.0.1 --port 9000
```

默认端口 9000；改端口不用改代码，设环境变量 `PORT` 即可。

## 首次登录

首次使用没有默认账号：打开页面注册首位管理员（用户名 + 密码，密码至少 6 位），注册后即关闭注册；后续管理员由首位管理员在“用户管理”里生成。

## 功能

- 登录 + 用户管理：用户名+密码登录，密码 PBKDF2 加盐哈希存储；任何管理员都能新增、改名、重置密码、停用管理员账号；**所有管理员权限相同，不分角色，都能看到进价、利润和全部功能**；关键操作写 `audit_logs`，页面可查最近操作记录。
- 首页：今天销售额、今天毛利估算、客户欠款合计、供应商欠款合计、低库存提醒（库存 <5 瓶）、本月自饮 / 赠送 / 破损 / 折扣统计。
- 酒库：条码、名称、品牌、规格、容量、度数、产地、厂家、图片上传（`uploads/`，jpg/png/webp，≤5MB）、说明手写；扫条码调网上接口自动带回信息。
- 多仓库；供应商 / 客户分开管理（新增、改、停用、删除，无单可删，欠款余额自动算；客户页显示累计获赠瓶数和成本）。
- 库存补登（期初，日期可回填，成本价可空）；进货单、出货单（含物流公司 / 单号 / 运费 / 包邮记 0 / 谁付，运费与货款分开算；付款状态未付 / 部分付 / 已付，可后续补记）；出货库存不足整单拦住，不允许负库存；调拨一键。
- 出库类型：销售 / 自饮 / 赠送 / 破损。自饮、赠送、破损都减库存、不算销售收入、不产生应收，按最新进价记成本；赠送记受赠客户，可按客户查累计获赠。
- 出货折扣（只针对销售）：可填折扣率（如 0.9）或折后单价，自动算原价、折后价、折扣额；打折必须填瑕疵 / 打折原因；利润和毛利按折后实收价算；分享图显示原价、折后价、折扣额和原因。
- 分享图片：进货单 / 出货单详情页“生成分享图”，Pillow 生成 PNG（宽 1080，白底黑字，适合发微信），只做图片不做链接。出货图给客户只显示卖价，不显示进价和利润；进货图给供应商只显示进价，不显示卖价和利润。自饮 / 赠送 / 破损单不做分享图。

## 条码接口

后端 `GET /api/barcode?code=xxx`，先查本地酒库，查不到再调网上接口：

- 环境变量 `BARCODE_API_URL`（接口地址，占位即可）、`BARCODE_API_KEY`（不要硬编码，不要提交到仓库）。
- URL 为空、调用失败或查不到时返回 `{"found": false}`，前端提示手填；查到则自动填名称 / 品牌 / 规格 / 厂家 / 参考价，图片 URL 会下载保存到 `uploads/`，不热链外站。
- 覆盖说明：支持 69 开头 EAN13 国产条码；进口条码覆盖低，新品可能查不到；查不到就手填一次存本地库，下次直接用本地数据。

## 数据与备份

- 数据库：应用目录下的 `vin_rouge.db`（可用环境变量 `VIN_ROUGE_DB` 改路径）；上传图片在 `uploads/`。
- 备份（应用内做，不用命令行）：管理页面 → 系统备份。应用启动后起一个后台循环，每天 1 时自动备份一次；启动时如果一个备份都没有，先自动备一份。备份用 sqlite3 backup API 生成一致性副本（WAL 安全，不能直接 `cp` 数据库文件），再 gzip 压成 `vin-backup-YYYYMMDD-HHMMSS.db.gz`，放在应用目录下的 `backups/`，每个备份带一个同名 `.json` 边车文件（创建时间、版本、种类、大小）。种类分自动 / 手动 / 恢复前三种。保留最新的 10 份，多了自动删掉。
- 管理页面能做的事：点“立即备份”手动备一份；备份列表每行显示时间、种类、大小、版本；点“下载”把备份文件下载下来；点“恢复”把数据恢复到备份那一刻。恢复前会二次确认，恢复前自动备一份当前数据（种类“恢复前”），恢复是把备份用 backup API 拷进正在用的数据库（不换文件），恢复后跑一遍数据库迁移、提示重新登录。
- 备份失败怎么发现：去管理页面 → 系统备份看列表，最近一次备份的时间超过一天没有更新就是有问题；也可以看服务日志里 `[backup]` 开头的行。
- 异地副本（备份只放 VPS 本机不够，丢盘就全没了）：把备份目录同步到 VPS 以外的一台机器，命令示例（二选一，`目标机器`换成自己的地址）：
  ```bash
  rsync -avz /opt/vin-rouge/backups/ 用户名@目标机器:/path/to/vin-rouge-backups/
  scp -r /opt/vin-rouge/backups/*.db.gz 用户名@目标机器:/path/to/vin-rouge-backups/
  ```
- 恢复演练步骤（正式启用前至少做一次）：① 去管理页面 → 系统备份，点一个备份的“恢复”；② 恢复前确认当前数据已被自动备份；③ 检查酒库、库存、单据、账款、付款、管理员都在；④ 确认能继续操作；⑤ 演练通过后再正式启用。
- 旧的定时任务（v2.10.0 的脚本做法已废弃）：如果 VPS 上以前装过 `vin-rouge-backup.timer`，先停掉它，不然新旧两套备份会重复跑：
  ```bash
  systemctl disable --now vin-rouge-backup.timer
  rm -f /etc/systemd/system/vin-rouge-backup.service /etc/systemd/system/vin-rouge-backup.timer
  systemctl daemon-reload
  ```
- 更新：`git pull` 后装依赖、重启服务即可，数据库文件不会被覆盖：
  ```bash
  cd /opt/vin-rouge && git pull origin main && ./.venv/bin/pip install -r requirements.txt && sudo systemctl restart vin-rouge
  ```
- 分享图中文需要系统装 CJK 字体，否则中文显示为方框：`sudo apt-get install -y fonts-noto-cjk`。

## 卸载（v2.11.0）

```bash
systemctl disable --now vin-rouge
rm -f /etc/systemd/system/vin-rouge.service
systemctl daemon-reload
rm -rf /opt/vin-rouge
```

注意：旧版 v0.4.0 的服务名是 `wine-system`、数据库是 `data/wine.db`，与新版不同，不要用旧版卸载命令删新版。

## 数据模型

`users`（无 role 字段，所有管理员权限相同）、`audit_logs`、`wines`、`warehouses`、`suppliers`、`customers`、`stock`（按仓库+酒+批次唯一，库存只通过单据增减）、`inbound_orders` / `inbound_items`（type = purchase 新进货 / opening 补登期初）、`outbound_orders` / `outbound_items`（type = sale 销售 / personal 自饮 / gift 赠送 / damage 破损）、`transfers`、`payments`（补记付款 / 收款，`paid_amount` 由 payments 合计推导，`pay_status` 由此推导：0 = 未付，< 总额 = 部分付，>= 总额 = 已付；运费不计入货款总额，单独列 `freight`；付款可撤销，撤销只打 `voided` 标记、不直接删行，已撤销的不计入已付）、`return_orders` / `return_items`（kind = sale 销售退货 / purchase 采购退货，关联原单原行，退货价冻结原行折后单价）。

利润按卖价减该酒最近进货成本价（或补登成本价）估算，首页显示，不做逐瓶精确批次成本核算。自饮 / 赠送 / 破损的成本同样按最新进价记。

## 版本演变

- **v2.11.0**（2026-11-26）：备份改成 fund 系统的做法（应用内备份，不用命令行）。后端：备份目录应用目录下的 backups/，保留最新的 10 份，文件名 vin-backup-YYYYMMDD-HHMMSS.db.gz；备份用 sqlite3 backup API 生成一致性副本（WAL 安全，不能直接 cp 数据库文件），写临时文件再 gzip 压缩，每个备份带同名 .json 边车文件（创建时间、APP_VERSION、种类、大小、是否压缩）；种类分自动/手动/恢复前；每次备份完按时间删掉 10 份以外的旧备份（连边车文件一起删）。恢复：先把备份解压到临时文件做完整性检查（PRAGMA integrity_check 通过、users 和 wines 表都在），不通过 400 拒绝；通过后先自动备一份当前数据（pre-restore），再把备份用 backup API 拷进正在用的数据库（不换文件，WAL 不乱）；恢复后重跑数据库迁移。备份文件名按正则校验（只允许 vin-backup-数字.db.gz），防路径穿越。后台循环每天 1 时（Asia/Shanghai）自动备份，启动时一个备份都没有先自动备一份；备份是阻塞 IO，放线程里跑。接口：GET /api/backups 列备份、POST /api/backups 手动备份、GET /api/backups/{name}/download 下载、POST /api/backups/{name}/restore 恢复（登录的管理员都能用）。恢复和备份之间用锁串行化，不互相踩。前端：管理页面加“系统备份”入口按钮和备份页，页里有立即备份按钮、说明文字（每天 1 时自动备份，保留最近 10 份；恢复前会自动备份当前数据）、备份列表；每行显示时间、种类（自动/手动/恢复前）、大小、版本；每行下载、恢复两个按钮。恢复要点二次确认（当前数据将被替换，恢复前会自动备份当前数据，恢复后可能需要重新登录），恢复成功提示后刷新页面。删掉 v2.10.0 的 scripts/backup.sh、scripts/restore.sh、scripts/vin-rouge-backup.service、scripts/vin-rouge-backup.timer，README 备份一节重写（旧的 systemd 定时任务要先停掉）。
- **v2.10.0**（2026-11-25）：单据页分类改货 + 钱双口径：未结单 = 货没走完，或者欠款 > 0（还有货款要补记）；已结单 = 货走完，并且欠款 = 0。已作废的单永远进已结单（不论余额多少），已关闭的单按欠款算；欠款比较前按分四舍五入，防浮点残差。预付（已付 > 应付，欠款为负）算钱已清；自饮/赠送/破损/补登没有钱，照常直接进已结单；调拨单没有钱，照常按货走完算；空状态文案和两级筛选、类型筛选不变。退货 / 纠错：销售退货单、采购退货单、付款撤销。销售退货从已确认的出货单卡片上点“退货”进入，预填已确认的行，每行退货数量 ≤ 该行已确认数量 − 已退数量（含待确认退货单的占用，确认时在事务内重新校验），退货价沿用原行折后单价（只读、冻结），退回仓库自选，每行选“正常入库”或“破损”，原因必填；两段式（下单不生效，确认才动库存和欠款，可分批确认，没确认过可整单废单，部分确认过只能废剩余变已关闭，全部确认完不能废单）；确认时正常入库的行库存 +数量、破损的行不加库存按成本记损耗，客户应收减少；原单卡片行上显示已退数量。采购退货对称，从已确认的进货单退，确认时库存 −数量、供应商应付减少。付款撤销：进货付款和出货收款都能撤销（不是直接删除），理由必填，只允许全额撤销，不可重复撤销，撤销后欠款恢复，写操作记录留痕。退货单在单据页里：销售退货在出货单类型下、采购退货在进货单类型下，卡片上有“退货”标签；退货单分类只按自身执行进度，不依赖原单欠款；退货后多付的部分按负余额显示（卡片上欠款为负显示“多付 ¥x”），不做自动退款。防超卖：所有减库存的操作确认时都校验（出货确认、调拨确认、采购退货确认、自饮/赠送/破损建单时），检查与扣减在同一事务内完成；库存不足时 400 拒绝，报错汇总所有缺货行，每行写明仓库、酒名、现有多少瓶、本次要多少瓶、缺多少瓶；不做预留量系统。备份与恢复：新增 scripts/backup.sh（sqlite3 .backup 在线备份，备份后自动验证文件、大小、完整性、核心表，验证通过才清理旧备份；保留每天 7 份 + 每周一份留 4 周）、scripts/restore.sh（恢复到临时目录做完整性检查和行数对照，不覆盖正在跑的数据库）、systemd 的 service + timer（每天自动跑一次备份）；README 加备份配置、失败发现方法、恢复演练步骤、异地副本命令。
